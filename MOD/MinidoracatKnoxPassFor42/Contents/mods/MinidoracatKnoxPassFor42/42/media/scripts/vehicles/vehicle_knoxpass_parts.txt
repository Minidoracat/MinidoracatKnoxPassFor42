/*
    感應盒零件槽的唯一定義：template 不會進入可生成車輛清單。
    MinidoracatKnoxPass/Parts.lua 在 OnGameBoot 把這一槽複製到每個有電瓶的車型，area 依車型改寫。
    不寫 items：感應盒用黏扣帶貼在擋風玻璃上，不需要工具；沒有 skills＝安裝必定成功
    （VehicleUtils.calculateInstallationSuccess，Vehicles.lua:1463-1485）。
    install／uninstall 兩個表都要有：原版拆除流程讀的是 install 表的 time 與 skills
    （ISVehiclePartMenu.lua:217,224、ISUninstallVehiclePart.lua:46-47）。
    mechanicRequireKey：要有車鑰匙或車門沒鎖才能拆裝（VehicleUtils.RequiredKeyNotFound，Vehicles.lua:1380-1389），
    鎖好的車偷不走感應盒。
    install／uninstall 的 complete：裝上或拆下後由伺服器呼叫（ISInstallVehiclePart.lua:95-98、
    ISUninstallVehiclePart.lua:65-67、Vehicles.lua:1327），把這顆感應盒登記的每一扇門改記新車／未裝在車上。
    itemType：7 色感應盒都能裝，分號分隔（VehicleScript.java:926-932 拆成清單；原版同寫法 generated/vehicles/template_brake.txt:60）。
    管理員「修理車輛」對空槽會從清單隨機挑一種裝上（VehiclePart.java:956-971 repair），所以修好的車可能是任一色。
    model Dock<顏色後綴>：擋風玻璃上的「固定座＋感應盒」，7 色各一個（id＝Dock＋KP.COLORS 的 suffix，米白就是 Dock），
    file 指向該色的模型腳本（models_knoxpass*.txt，scripts/gen_colors.py --check 核對）。每個都要寫 file：
    零件沒有 parent 時，畫面上的模型用 scriptModel.file 取動畫（BaseVehicle.java:11844-11853），file 是 null 會在
    ScriptManager.getModelScript(null) NPE、客戶端踢回主選單（ScriptBucketCollection.java:73）；原版 HoodOrnament
    不寫 file、改由物品的 VehiclePartModel 指定，是因為它有 parent = EngineDoor。
    setAllModelsVisible = false：不讓引擎在 setInventoryItem 時 7 個全開（VehiclePart.java:148-182）；
    顯示哪一個由 MinidoracatKnoxPass.syncDock 決定（Parts.lua，lua.init 與安裝／拆下的 complete、零件 update 都會呼叫）。
    offset／rotate／scale 是佔位值，Parts.lua 注入時依各車型改寫 7 個 model（原版車查 DockSpots.lua、其他車用腳本幾何推算）。
*/
